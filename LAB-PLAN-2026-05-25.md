### 3.2 Modelos JSON

#### `~/.yt-content-pipeline/lab/channels.json`

```ts
interface ChannelDraft {
  id: string;                       // uuid
  createdAt: string;                // ISO
  updatedAt: string;                // ISO
  status: 'draft' | 'validated' | 'bootstrapped' | 'in-production' | 'archived';
  currentStep: 1 | 2 | 3 | 4 | 5;   // dónde está el wizard
  // PASO 1 — Referencia
  referenceChannelUrl: string;
  referenceChannelName?: string;    // resuelto vía Algrow
  language: 'en' | 'es' | 'pt' | 'it' | 'fr' | 'other';
  initialTopic: string;             // tema concreto OR "ideas-please"
  transcripts: string[];            // 2-3 transcripts completos pegados
  // PASO 2 — Análisis style-engine
  channelAnalysis?: string;         // bloque ANÁLISIS DEL CANAL
  styleDna?: string;                // bloque STYLE DNA
  scriptSample?: string;            // script style-locked generado
  scriptTarget?: { words: number; minutes: number; wps: number };
  // PASO 3 — Visual
  sampleFrameUrls: string[];        // URLs/paths de 3-5 frames del vídeo
  visualStyleProfile?: string;      // bloque VISUAL STYLE PROFILE
  imagePrompts?: Array<{ beat: string; prompt: string; cameraAngle: string; lighting: string; mood: string; action: string }>;
  thumbnailSampleUrls: string[];    // 2-3 thumbnails de referencia
  thumbnailStyleProfile?: string;   // bloque THUMBNAIL STYLE PROFILE
  thumbnailConcepts?: Array<{ visual: string; textOverlay: string; emotionalTrigger: string; prompt: string }>;
  // PASO 4 — Validación
  validation?: {
    verdict: 'green' | 'yellow' | 'red';
    demandScore: number;            // 0-100
    saturationScore: number;        // 0-100
    wedges: string[];               // ángulos defendibles
    risks: string[];
    referenceChannelsRecommended: Array<{ name: string; url: string; reason: string }>;
    keywords: Array<{ keyword: string; volume: number; competition: number }>;
    rawReport: string;              // markdown completo
    runAt: string;                  // ISO
  };
  // PASO 5 — Bootstrap
  bootstrap?: {
    chosenName: string;
    chosenHandle: string;
    chosenDescription: string;
    descriptionVersion: 'A' | 'B' | 'C';
    logoPrompt: string;
    bannerPrompt: string;
    assetGenerationMethod: 'canva-mcp' | 'nano-banana-manual' | 'both';
    diskPath?: string;              // H:/YOUTUBE/<NAME>/ — set al ejecutar bootstrap_channel.py
    bootstrappedAt?: string;
    skillCreated?: boolean;         // si Pablo eligió crear skill especializada (state 15)
    skillPath?: string;             // Y:/.claude/skills/<channel-slug>/SKILL.md
  };
  // Jobs claude lanzados por este draft (para historial)
  jobIds: string[];
}

interface ChannelsState {
  version: 1;
  drafts: ChannelDraft[];
}
```

### 3.4 Integración con `style-engine`

`lib/lab/style-engine-runner.ts` construye prompts ESPECÍFICOS por pantalla y los lanza vía `startJob()` de `lib/claude-jobs.ts` (mismo patrón que SARA et al.). El job corre con `cwd=Y:/04_DEV/J.A.R.V.I.S` para que claude vea la skill `style-engine`.

**Prompt construido para Pantalla 2** (states 1-6):

```
ENGINE, ejecuta los STATES 1 a 6 en secuencia para este canal:

STATE 1 — CHANNEL LINK
{referenceChannelUrl}

STATE 2 — TRANSCRIPTS
{transcripts[0]}
---
{transcripts[1]}
---
{transcripts[2]}   (si existe)

STATE 3 — TOPIC
{initialTopic === 'ideas-please' ? 'Genera 5 ideas alineadas con el nicho y elige la primera' : initialTopic}

STATE 4-5-6 — ejecuta análisis, Style DNA y genera script style-locked.

IMPORTANTE: NO uses tu modo interactivo de "para después de cada estado".
Esta es una sesión claude -p, NO interactiva. Ejecuta los 6 estados de tirón
y entrega los outputs en bloques delimitados con los headers que ya usas
(───── separadores). Al final, termina con la línea exacta:

<<<DONE>>>
```

`parse-engine-output.ts` extrae cada bloque por regex sobre los headers
(`ANÁLISIS DEL CANAL`, `STYLE DNA`, `WORD COUNT FINAL`, etc.) y los guarda
en el draft.

**Prompt construido para Pantalla 3** (states 7-13, sin 10): similar pero
recibe ya el contexto de la pantalla 2 (analysis + dna + script). Los frames
y thumbnails se pasan como rutas absolutas en el filesystem para que claude
las lea con su Read tool. style-engine los procesa.

**Prompt construido para Pantalla 5** (state 16 completo): incluye en el
contexto todos los outputs de pantallas anteriores + el veredicto del
validador. Ejecuta B1-B7. B6 corre el script python real
`bootstrap_channel.py` que crea la estructura en disco. B7 devuelve el
resumen final.

### 3.5 Validador de nicho

`lib/lab/niche-validator.ts` orquesta secuencialmente:

1. `mcp__algrow__resolve_url(referenceChannelUrl)` → handle + channel_id.
2. `mcp__algrow__channel_trends(channelId)` → tasa de crecimiento.
3. `mcp__algrow__search_viral_videos(niche, daysBack=90, minVPH=3)` → outliers.
4. `mcp__algrow__search_longform_channels(niche, language)` → competencia.
5. Spawn job claude con skill MARIO + contexto consolidado de los pasos 1-4.
6. MARIO devuelve veredicto + scores + wedges + risks.
7. Persistir resultado en `draft.validation` y `research.json` (modo deep).

Veredicto:
- 🟢 si demand >70 + saturation <60 + ≥1 wedge defendible.
- 🟡 si valores intermedios o algún wedge cuestionable.
- 🔴 si demand <40 o saturation >85 sin wedge claro.

### 3.6 Pipeline interactivo "primer vídeo"

`/lab/first-video/[draftId]` muestra una timeline vertical con las 6 fases
del kanban. Cada fase es una "tarjeta" expandible con:

- Estado (pendiente / en progreso / completo).
- Botón para activar las skills correspondientes con un click.
- Output del último job de esa fase.

Fases y skills:

1. **Packaging** — MARIO (validación topic) → MARCOS (4 títulos) → NORA+IRIS (concepto miniatura).
2. **Creación (guion)** — MARCO AURELIO (si canal estoico) o VÍCTOR → ELENA (audit).
3. **Visual (image + video prompts)** — IRIS → CIRO.
4. **Audio (locución)** — CICERÓN → CALIOPE.
5. **Edición** — LUÍS.
6. **Pre-publicación** — youtube-seo-optimizer → chapters → upload.

El "primer vídeo" se materializa en disco como una carpeta bajo
`H:/YOUTUBE/<nuevo-canal>/_EN PRODUCCIÓN/<title-temporal>/`. A partir de ahí,
el modal de vídeo existente (`VideoDetailModal`) ya cubre todo el flujo —
el pipeline interactivo es básicamente una vista "wizard" alternativa
que abre el modal con highlighting de la fase siguiente.
