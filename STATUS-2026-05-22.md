## 🔴 BUG CRÍTICO ACTUAL (prioridad 1 para próxima sesión)

### Síntoma

Cualquier botón de skill (SARA, ELENA, AMELIA, MARCUS, LUIS, NORA+IRIS, resolve checklist) arranca un job. El proceso `node.exe + cli.js -p` se crea (PID válido, memoria normal ~190MB), pero **consume solo ~8 segundos de CPU en 7+ minutos**. Está IDLE, no procesando. El log permanece vacío después del prompt header. Status del job: `running` indefinidamente.

### Lo que SÍ funciona

- `claude -p "prompt"` desde una terminal interactiva (PowerShell): responde en segundos.
- `echo "prompt" | claude -p` desde bash: idem.
- Endpoint VIEJO `/api/claude/run` (sync, sin persistencia): ELENA funcionó la primera vez con informe completo.
- Terminal embebida (node-pty con PTY real): conversación normal con claude funciona.

### Lo que NO funciona

- Endpoint NUEVO `/api/claude/jobs` (persistente). Spawn con:
  ```ts
  spawn('node.exe', [cliPath, '-p'], {
    cwd, shell: false, detached: true, windowsHide: true,
    stdio: [stdinFd, out, err],   // stdin = fd a archivo .prompt.txt
    env: { ...process.env, TERM: 'dumb' }
  })
  ```

### Bugs ya descartados (resueltos antes de llegar aquí)

1. **spawn con shell:true + cmd.exe wrapper**: cmd.exe no propagaba stdin al cli.js de claude. → resuelto invocando `node.exe + cli.js` directo.
2. **spawn EINVAL al usar `claude.cmd` con shell:false**: Node 18+ bloquea `.cmd` sin shell por seguridad CVE. → resuelto saltándose el wrapper.
3. **Prompt vía pipe Node→child requería pipe vivo**: incompatible con `detached:true` (proceso muere al cerrar padre). → resuelto pasando prompt vía file descriptor.

### Hipótesis del bug actual

Probablemente claude detecta que stdin viene de un file descriptor regular (no TTY ni pipe interactivo) y entra en un modo "esperar más input" o "comprobar interactividad" que se cuelga indefinidamente. La diferencia clave con la terminal interactiva: ésta usa PTY real vía node-pty.

### Soluciones a probar (en orden de simplicidad)

1. **Pasar el prompt como argumento, no por stdin**: `spawn('node.exe', [cli, '-p', promptString], ...)`. Node con `shell:false` y array escapa correctamente. Requiere validar tamaño máximo (algunos prompts son ~5KB).
2. **Quitar `windowsHide: true`**: puede que el cli.js detecte hidden console y se comporte distinto.
3. **Quitar `TERM: 'dumb'`**: puede que esté afectando al loop de stdin del cli.
4. **Probar `stdio: ['ignore', out, err]`**: si claude no necesita stdin (porque el prompt va por argumento), ignorar stdin entero.
5. **Investigar flags del cli.js de claude code 2.1.x**: quizá hay `--input-file <path>` o `--no-stdin` que evite el modo espera.
6. **Patrón "PTY pequeño via node-pty"**: si todo lo anterior falla, spawnear claude detached A TRAVÉS de un pty efímero. Más complejo pero replica las condiciones de la terminal interactiva que SÍ funciona.

### Cómo verificar el fix

Lanzar un botón ELENA sobre el vídeo `10 Stoic Practices That Quiet Anxiety in 7 Days` (tiene guion, ELENA tiene material para auditar). Resultado esperado: log se llena de output progresivo en 30-90s, status pasa a `done` con `outputOnly` no vacío.

## Decisiones técnicas registradas

| Decisión | Razón |
|---|---|
| `lib/progress-types.ts` separado de `lib/progress.ts` | Tipos puros browser-safe (sin `node:fs`), evita el bug `UnhandledSchemeError` cuando un componente client importa tipos del módulo server-only |
| `import 'server-only'` en `lib/progress.ts` y `lib/claude-jobs.ts` | Falla en build si un componente client lo importa por error |
| `shrink-0` en `<VideoCard>` | Antes las cards se COMPRIMÍAN cuando había muchas en una columna con `max-h + overflow-y-auto + flex-col`. Con `shrink-0` mantienen altura natural y aparece scroll de verdad |
| `object-contain` en miniaturas | Antes con `object-cover` se recortaba texto inferior. Con `contain` aparecen bandas negras si la miniatura no es 16:9 nativa, pero se ve completa |
| Modales `absolute inset-0` en vez de `fixed` | Para que respeten el espacio del TerminalDock a la derecha |
| `max-h-[55vh]` al video del modal | Antes ocupaba toda la pantalla y tapaba el resto del modal |
| `md:grid-cols-3` con `col-span-2 / col-span-1` en vez de `lg:grid-cols-[2fr_1fr]` | La sintaxis arbitraria fallaba en algunos viewport; el grid estándar funciona |
| Disabled por hito en cada botón de skill | ELENA needs scriptWritten, AMELIA/MARCUS need renderPrincipal, LUIS needs locucionReady+scriptWritten. SARA siempre activa (su trabajo es arreglar) |
| node.exe + cli.js directo (no claude.cmd) | Saltarse cmd.exe wrapper que rompe stdin propagación |
| Prompt vía file descriptor (no pipe) | Para que el proceso sea verdaderamente detached (pipe vivo mata persistencia) — **PERO esto es lo que está rompiendo claude actualmente** |
